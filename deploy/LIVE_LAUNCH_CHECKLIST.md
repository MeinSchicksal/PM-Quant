## 一、上线总原则与三步灰度节奏

切忌“纸面跑顺就直接重仓上真钱”。严格按三阶段推进，**上一阶段验收不通过，绝不进入下一阶段**：

1. **阶段一 · 纸面满周期验证（当前阶段，周期 10 ~ 14 天）**
   - 保持当前已封板的 `v3.4` 在伦敦机房稳定运行，不频繁手痒调参；
   - 攒满至少 **2,000+ 场**横跨不同市况（单边、震荡、周末低波、消息面波动）的纸面样本，以及 **14 天**自动压缩归档的 L2 原始行情数据。
2. **阶段二 · 极小资金实盘探路（周期 3 ~ 5 天，独立热钱包 `\$50 ~ \$100`，单笔死守 5 股）**
   - **核心目标不是赚钱**，而是跑通真钱下单、成交回报、余额对账、自动赎回全闭环，并实测 **“真钱 vs 纸面”的真实成交率与滑点衰减**。
3. **阶段三 · 对账通过后小步放量**
   - 仅当真钱跑满 200 ~ 300 场、实测扣完真实滑点与手续费后仍为显著正期望，再逐步解锁 10 股加仓或按盘口深度容量缓慢扩资金。

## 二、阶段一验收门槛（纸面稳跑 10 ~ 14 天结束时复核）

- [ ] **样本量达标**：伦敦机房连续运行 ≥ 10 天，有效交易场次 ≥ 1,500 ~ 2,000 场
- [ ] **跨市况稳定性**：按自然日 Walk-Forward 统计，盈利天数占比健康，无因程序 Bug 导致的异常大亏日
- [ ] **核心指标复核**：
  - [ ] 累计净收益与单场期望显著为正（`t` 统计量健康）
  - [ ] 实测最大回撤在心理与本金承受范围内
  - [ ] 滚动模型 Brier 准度持续优于或持平盘口（确认模型仍有定价优势）
- [ ] **基于 14 天压缩 L2 数据做一次上线前专项回测**：
  - [ ] 用 Polymarket 5m 市场官方真实 Taker 费率（`0.05` vs 当前保守 `0.07`）复检边际门槛
  - [ ] 评估是否引入盘口深度不平衡（OBI）或副源大所（如 OKX/Bybit 永续）做防毒共识校验
  - [ ] 确认最终上实盘的一套冻结参数，不再临阵乱改

## 三、实盘上线前必须开发的 5 大保命模块（缺一不可）

### 1. 真实 CLOB 执行层与交易所真相强制对账（`LiveExecutor`）
- [ ] 接入官方 CLOB 签名下单客户端（预热 HTTP/2 Keep-Alive 长连接 + 预缓存合约 `tick_size` / `neg_risk` / 授权状态，降低提交耗时）
- [ ] 接入 **Polymarket User Channel WebSocket**（个人订单状态与真实成交实时推送），以交易所回报为唯一真相
- [ ] **发单超时幂等查证**：下单 HTTP 超时或网络抖动时，**严禁盲目重发**；必须先查单确认订单状态，避免重复开仓或双边裸奔
- [ ] **每轮前后真实持仓/余额强制对账**：本地账本持仓 vs 交易所真实持仓一旦出现偏差，立刻锁死暂停开新仓并触发最高级告警
- [ ] **结算后自动 Redeem（赎回 USDC）**：赢单交割后自动赎回至可用余额，避免资金滞留在已结算合约导致后续无钱反手
- [ ] **Paper / Live 双模式显式开关**：默认仍为 Paper，需显式配置环境变量与启动参数才允许激活真钱下单，防误触

### 2. 账户级硬风控与「Alpha 衰减急刹」看门狗
- [ ] 打开账户级硬熔断（`config.py` 中 `ENABLE_CIRCUIT_BREAKER = True`）：
  - [ ] 设定单日最大回撤硬上限（例如本金的 15% ~ 20%，如 `\$100` 本金设 `\$15 ~ \$20`）
  - [ ] 设定合理连亏冷却策略（防止极端连杀期持续失血）
- [ ] **新增真钱执行恶化熔断（防对手变快、好单被抢光）**：
  - [ ] 滚动 20 笔真实 Taker IOC 拒单率 > 70% 时，自动暂停/降频并报警
  - [ ] 滚动真实成交滑点均值 > `\$0.025` 时，自动暂停并报警
- [ ] **真钱 vs 纸面影子对账（Shadow Comparison）**：
  - [ ] 同一触发信号同时记录“纸面理论成交价”与“实盘真实成交价”，量化真实执行损耗
- [ ] **Alpha 衰减早期预警**：
  - [ ] 监控每日出手率骤降、滚动 100~200 场胜率跌破底线、滚动 Brier 准度反转输给盘口，触线自动停机并告警

### 3. 钱包资金隔离与私钥安全
- [ ] 新建**独立专用 Polygon 热钱包**，只转入实盘测试本金（起步 `\$50 ~ \$100`），与主资产钱包彻底隔离
- [ ] 私钥、CLOB API Key / Secret / Passphrase **仅存服务器 `/etc/pm-quant.env`**，权限设为 `chmod 600`，**严禁提交到 Git 仓库**
- [ ] 在最底层下单函数内**硬编码单笔金额与单日总下注上限**（例如单笔绝不超过 `\$15`），兜底防任何上层逻辑 Bug 刷光余额
- [ ] 检查 Polygon 钱包内留有少量 POL (MATIC) 用于自动 Redeem 等链上 Gas 费

### 4. 7×24 手机告警与一键急停开关（Kill Switch）
- [ ] 在 `/etc/pm-quant.env` 中配通 `runtime/alerts.py` 外部推送渠道（任选其一或多个）：
  - [ ] Telegram Bot (`PM_TELEGRAM_BOT_TOKEN` + `PM_TELEGRAM_CHAT_ID`)
  - [ ] iPhone Bark (`PM_BARK_URL`)
  - [ ] 飞书 / 钉钉 / Discord (`PM_ALERT_WEBHOOK_URL`)
- [ ] 实测告警通道畅通，确认以下事件 30 秒内必达手机：持仓对账不一致、连环拒单、日回撤熔断、余额不足、API 格式变更暂停、进程重启
- [ ] **实现一键急停开关（Kill Switch）**（支持看板按钮 + 服务器命令）：一键进入“只撤不买”安全态（撤掉所有挂单、禁止新开仓、等待现有持仓自然结算）
- [ ] （可选）增加每日北京时间 08:00 自动推送昨日收益日报

### 5. 已知宏观黑天鹅日历静默窗（可选，推荐）
- [ ] 在每月已知重大宏观数据公布窗口（美国 CPI、非农 NFP、美联储 FOMC 利率决议）前 10 分钟 ~ 后 15 分钟暂停开新仓，避开无序跳空与盘口抽干

## 四、实盘灰度期监控清单（上线前 3 ~ 5 天每日必看）

- [ ] **真实成交率**：真实 IOC 成交笔数 / 触发信号总笔数（是否明显低于纸面？）
- [ ] **真实滑点**：`实际成交均价 - 信号触发时 ask` 均值是否在 `\$0.01` 以内？
- [ ] **逆向筛选偏差**：验证“成交的单”和“没抢到的单”胜率差异（警惕“好单全没抢到、毒单全成交”）
- [ ] **真实手续费核对**：核对 Polymarket 实际扣费是否与预期 `0.05 * p * (1-p)` 一致
- [ ] **自动 Redeem 与可用余额**：确认每轮赢单资金能按时回笼，无卡单、无余额不足导致反手失败
- [ ] **网络与进程健康**：确认 `pm-quant-engine` 内存占用稳定、无 OOM 重启、无 WS 频繁断连
